## Assumptions and deviations (all made without asking, per Step 13)

- Materials are versioned with the other rate tables (the brief listed `materials` outside `rate_*`) so old quotes re-price identically; quotes also store the full priced result.
- A part's thumbnail is stored inline as SVG text (`parts.thumbnail_svg`) instead of a storage path — no extra signed-URL round trips in lists.
- Thickness above the laser limit is **amber** (`laser.thickness_over_limit`) when a supplier row exists — sendable after confirmation — and red only when no rate exists at all; otherwise no part above 12.7 mm could ever be quoted.
- Red flags are never overridable (Step 2: "no quote can be sent with a red flag"); override requests apply to amber flags. An amber "confirmation" is stored as a self-approved override row (note "confirmed by sales") so it is audit-logged.
- Slow-contour factor applies in time mode only; supplier per-metre rows are priced on the plain length.
- Welding-only handling per part lives in `rate_general.weld_handling_per_part` (the brief's `handling_per_part` belonged to the tube table).
- The first account created in the project becomes admin; roles can only be set by an admin or via app metadata.
- STEP files create a stub part and prompt for manual entry (no STEP parsing, per Step 13).
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` / `SUPABASE_SECRET_KEY` are accepted as aliases of the legacy variable names.
- The two customer DXFs were fetched from the owner's OneDrive folder `200009_A` by copying each as a `.txt` inside OneDrive, reading it and deleting the copy (the copies sit in the OneDrive recycle bin). One cp1250 byte in a linetype name was restored to match the original size exactly.
- A temporary `smoke-test@stretchmetal.local` account was created in the Supabase project for a browser test and deleted again once the container's network policy turned out to block Supabase.
